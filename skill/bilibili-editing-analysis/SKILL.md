# B站多维剪辑拆解

按原片实际样式分析，B站不代表固定节奏、手法或模板。用户要求借鉴 B站剪辑时调用本 Skill；不预设单一转场或把镜头检测当成分析。若原片来自链接，先通过 `video-link-extractor` 获取可解码且身份匹配的原片；已有原片复用并校对视频身份、哈希与时长。涉及脚本、逐画面素材和飞书归档，衔接 `analyze-folder-videos-to-feishu`；用户要实际剪辑时使用可用编辑工具，剪辑方案不等于已交付视频。

## 全片到可执行剪辑

1. 完整观看并听取原片，记录可用画质、音轨及未覆盖区间。按内容功能与观感分阶段：开头、叙事展开、解释、展示、收束等以实际为准，不强套结构。记录说话、素材、声音与画面层的关系。
2. 复用已有核准镜头表；检测只能提供候选切点。逐项看切点前后及内部画面，连续观察逐渐变化或难辨特效，判断真正场景、角度、画面内容变化；加字、动画或拉近不必视为新镜头。切点、范围、画面编号、脚本段及来源标识互相关联。
3. 至少检查**镜头节奏与时长、画面构图与运动、剪接与转场、文字/字幕/图形、画面特效与合成、配乐/环境音/音效/人声、声画衔接**。包括实际出现的画中画、蒙版、遮罩、叠图、调色、重影、定格、加速/慢速、跳切、卡点、音桥等，也允许未列出的新手法。只写实际能看听到的，缺席写“未观察到”，不清楚写“待核”。区分实际观察、可能的剪辑实现和原因推测。字幕高亮、页面截图与视觉叠加不直接推断为特定软件或插件。
4. 分层输出：整片节奏曲线和阶段逻辑；有时间范围的关键手法与变化节点；逐镜/语义段对应的剪辑执行表。每行包括源开始结束和时长、画面编号、口播或脚本对应、素材入口、画面动作与构图、剪点/转场、文字/包装、特效、声音、可操作复刻步骤、证据与不确定项。多个不连续源区间分别列出；新配音时长标估计或实测，不把原片时长当新配音实测。特效按层、起止、运动方向、关键帧和叠加关系说明；无法确认参数用可调整范围，不伪称精确插件参数。
5. 若镜头边界和覆盖范围已人工复核，可运行 `scripts/pacing_metrics.py` 汇总镜头时长、中位数、切点/分钟和分段指标；所有输出仅为输入时间线计算，不认证视觉判断。音乐节拍、音效与节奏关系需要实际听校或可靠音频证据；音频不可访问则标注未验证。不得从文字/静帧推断BPM、卡点、留存或转化。
6. 提供可替换的剪辑思路，保留口播主体、音轨和叙事连续性。先给执行步骤和素材要求；如果用户希望存入飞书，用现有产品/平台/视频关联及已授权目标，先查字段再写入回读。不要声称剪辑工具、素材、效果或飞书交付已完成，除非实际验证。

交付前记录视频 ID、来源哈希、覆盖区间、检查方式、内容和手法证据时间点，明确未观看/未听校范围。跨案例提炼多种可选方法及适用条件，避免把某一案例习惯固化成统一模板；不能证明某手法带来爆款或真实投放结果。

计算时，将人工核准且在覆盖区间内连续无间隙的镜头写入 JSON：`{"review_status":"reviewed","source_sha256":"实际原片SHA256","coverage_start_sec":0,"coverage_end_sec":5,"shots":[{"start_sec":0,"end_sec":2},{"start_sec":2,"end_sec":5}]}`。运行 `python scripts/pacing_metrics.py --input <已核准镜头.json> --output <新结果.json>`；分段计算分别提供各自的覆盖区间和镜头输入。脚本不看视频、不验证源文件哈希的真实性或人工核准的质量。
