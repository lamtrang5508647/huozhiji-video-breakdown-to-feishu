# 课程方法：从源片理解到可执行内容任务

用于带货视频深拆，以及用户明确要求的选题、脚本、拍摄计划、创意测试和数据复盘。先确定是**解释源片**还是**生产本品内容**；前者只增强既有分析，后者另建本地创作文件。课程方法不改变原文、分段、短语颜色、镜头编号、复核和飞书交付合约。

## 来源与采用边界

本方法原创归纳自用户提供的《众星引力课程笔记（完整版）》（111 页）与《众星引力笔记》（3 页）。下文及 [course-rule-cards.json](course-rule-cards.json) 的页码均为 **PDF 从 1 起计的页序号**，不是纸面页码；例如完整版 PDF 第 20 页的纸面页码为 19。分发包不包含原 PDF、逐页转写、长引文或课程截图。

完整版的结构、表格和对照例主要以页面图像核对，OCR 只作导航。短笔记可作索引；它把情境经验压缩成固定比率、单向因果、万能结构、产量和人员配比，不直接继承这些结论。规则卡区分 `adapted`（有条件采用）与 `excluded`（明确排除），每卡带来源页、条件、操作、例子、反例和落点。

采用：双结构、多个可视化思路、可观察拍摄标准、需求时刻、视角、可检索内容资产、探索与迭代、反馈修正。限定：课程的“高转化”“种子”仅为原讲述标签；自己的效果需自己的数据。排除：买评论/伪造好评、借名人或专家身份、用生成画面假证实功效、遮挡关键信息或变换素材规避审查、收益保证、自动投放和固定预算建议。

## 先判断当前任务

| 用户意图 | 执行与输出 | 不自动扩大到 |
| --- | --- | --- |
| “拆这条视频/比较参考片” | 保留源片证据，按双结构和购买问题解释；沿用既有章节、语义段及逐画面库 | 本品创意任务、重写已保存章节、广告操作 |
| “按本品改写/出选题/给摄影拍摄单” | 建独立 `creative_workflow.py` bundle；按所需交选题、脚本、拍摄、测试卡 | 把本品方案写回源字幕/源事实，自动 AI 生成 |
| “批量拆/继续上次” | `workflow_batch.py` 保存逐文件状态；处理可运行的本地步骤，人工完成分析和复核 | 用 ASR/检测器替代理解，未复核自动发布 |
| “导入报表/哪种表达值得保留” | `performance_feedback.py` 导入有口径的实测数据，回查准确变体 | 将点击等同成交，自动扩量或修改预算 |

没有源片但有明确本品资料时，也可写原创探索任务；来源标为本品资料与创作假设，不能伪造参考视频 ID。缺事实的部分保留具体待补项，不让一个缺口阻止其余有依据的工作。

## 1. 用两条线解释一个完整语义段

完整版 PDF 20、90、94 页提示：文案逻辑与画面展开必须分别观察。逐段先做下面的记录，再解释对应关系；不为凑框架重排源片或硬切前三秒。

| 记录 | 要写什么 | 收纳盒原创示例 |
| --- | --- | --- |
| 原句及来源 | 实际口播/字幕、时间、校对状态；两者不同分别记 | 字幕“抽屉怎么还是乱？”；仅字幕摘录，未听校 |
| 文案逻辑 | 本句提出/回答什么，条件与结论如何衔接 | 提出收纳困扰，随后解释隔板如何分区 |
| 画面次序 | 人/物、动作开始—变化—结果、构图、场景；只写看见的 | 俯拍零散小物→移入两格→手推回抽屉 |
| 声画关系 | 重复、补充、演示、反差、冲突或氛围；支持到哪里 | 分区动作演示摆放方式；不能证明节省了多少时间 |
| 复用条件 | 保留什么关系，本品要补什么，切片需带什么上下文 | 保留“问题→分区过程”，先核尺寸；保留装入与关合的连续动作 |

源片的“吸引注意”属于解释，不属于画面描述；“手把盒子推入抽屉”属于观察，不能只换成“痛点镜头”。主张仍进 `source_claims`，源片展示材料进 `source_evidence`，不能把材料自动标独立验证。没有完整音频证据时不写“重音/停顿使观众相信”。

原片顺序用于解释；新片顺序是独立创意决定。课程的内容生产优先级也不等于成片顺序：对于新产品，先明确能支持的主张与展示，再找需求情境，最后打磨开头；若主张已可靠而开头理解有问题，可以优先测试开头。此优先级不能据单个低 CVR 直接断言某个镜头无效。

## 2. 从需求时刻做选题，不从大人群标签堆标题

完整版 PDF 34–35、76 页分别涉及场景、表达视角和需求。使用四个不同问题：

1. **谁在何时做什么？** 写具体行为与约束，而非“精致女性/所有宝妈”。
2. **此时遇到什么阻力、想完成什么？** 这是需求假设；来源可以是真实问题、访谈、源片观察或作者假设，分别标明。
3. **本品哪个已核实事实可能有关？** 事实、卖点主张、主张证据分开。可拆隔板是结构事实，不自动证明“空间翻倍”。
4. **用什么视角回答？** 用户视角讲可核实使用情境，商家视角解释设计取舍，专业视角仅在真实资格/资料范围内解释。不因品类就编医生、专家或用户经历。

把候选写成“需求时刻 × 可回答的问题 × 支持该回答的事实/材料 × 视角”，筛选时比较相关性、证据可得性、拍摄可行性和差异，不用虚构综合分。选题库须能按这些维度和来源检索；一句热门标题不是完整选题。

真实提问库只收有来源的问题：保留原文、平台/原帖定位、采集日期、语境、匿名化标识、是否取得可展示授权及回答状态。`comments` 中真实提问需本地存档、哈希及可核对的原句；缺出处的“用户说”先列入 `decisions[].remaining_objections` 待核实，不伪填 `real_user`。归纳多个问题时标为归纳而非逐字原话。提问可成为选题输入，但不代表市场比例、购买效果或授权发布。完整版 PDF 62 页的付费评论包装做法明确不采用。

具体落点：收到转述“有人问能否放进窄柜”时，在 `remaining_objections` 写“用户转述的尺寸疑问，未见原文；待补原帖和日期”，选题只作需求假设。取得原文、带时区采集时间、原帖定位及本地存档哈希后，新增真实 `comment_id` 记录；原待补项注明“已补至该评论 ID、仍需语境/展示授权核对”。用新 bundle 修订保留此前待补状态，不能倒填成早已核实。

## 3. 为主卖点比较不同展示机制

完整版 PDF 23、34、71、76 页：创意探索时，围绕一个已支持的主卖点，尝试约三种不同的可视化机制，例如真实操作过程、可比条件对照、适用场景、结构细节。**这是新方案探索启发，不是每条源片必须有三个镜头、每个脚本必须塞三次展示或三份功效证明。** 只有一种真实可行的机制时就保留一种并说明限制；少而可信优先于补数量。

每个候选都回答：要传达哪一项事实/主张；谁在哪里做什么；用户能直接观察到什么；为什么比另一方案易理解；需要哪些真实物料/身份/测试条件；哪里仍不能由画面证明。先搜已有镜头与表达模块，再决定剪辑复用、重拍、补资料或放弃。

收纳盒“可拆隔板”的三种候选：俯拍取下隔板展示结构；连续装入不同尺寸物件展示可调整布局；同一位置的两种分区并列展示选择。它们不能证明耐重、永久耐用或适合任何抽屉。不能简单以远/中/近三个景别冒充三种解释机制。

候选不是有效表达。`expression_modules` 保存实际文案/视觉关系、源视频/段/材料引用、适用需求、必需事实和复用限制。未经本品实测只可称候选或待测试；竞品热度、课程案例、结构校验通过都不能升级为本品已跑通表达。

## 4. 把“拍好看”改成可验收拍摄要求

完整版 PDF 24、26、90 页的对照适合转为观察标准；不沿用其从画面差异直接推断销量的因果结论。

| 检查点 | 交给拍摄/剪辑的要求 | 退回例 |
| --- | --- | --- |
| 主体与动作 | 明确拍谁/什么；动作开始、变化、结果均可辨；保留必要连续性 | 卡扣被手遮住，剪掉扣合瞬间却称易扣合 |
| 景别/机位 | 为信息选择，写主体大小和角度，不只写“高级感/特写” | 斜角看不到隔板与盒底连接处 |
| 光线/色彩 | 关键信息曝光正常，肤色/产品色不过度改变；记录对照条件 | 前后对照更换曝光、滤镜，却称产品效果 |
| 道具/服装/场景 | 不抢信息，不改变容量、身份或效果；明确尺寸和替代限制 | 用不同大小容器制造容量差，衣服图案遮住操作 |
| 声音/文字 | 要听到的自然声与口播任务分开；字幕不遮动作、量尺或限定条件 | 加强音效被写成产品真实声音，静音片被补拟口播 |
| 时长与剪辑 | 给足辨认动作/读数所需时长；拍后回看决定有效窗口 | 把结果闪过称“已充分展示”，为统一时长切掉条件 |

拍摄卡写一个合格条件和一个失败例；适用项必须具体，不适用项写理由。计划中的机位/灯光属于建议，不能回填为源片已知拍摄参数。效果/对照类素材优先真实拍摄并记录一致条件；生成画面只能作标明的示意或创意草稿。

## 5. 四类任务卡与两种工作模式

目标产品工作保存为与源分析分开的 bundle。用安装目录下 `scripts/creative_workflow.py init --help` 创建实际版本模板，再按 `validate --help` 校验；以该版本模板字段为准，不把下表的业务要求当作未实现的 JSON 字段。各卡通过稳定的产品、变体、事实、来源及材料 ID 串联。

| 卡（bundle 位置） | 使用者收到的决策 | 完成标准 |
| --- | --- | --- |
| 选题 `cards.topic` | 需求时刻、问题出处、表达视角、主次卖点、证据与选择/淘汰原因 | 能说明为什么值得写，以及什么信息尚缺 |
| 脚本 `cards.script` | 段落目标、原创新句、对应画面/声音、必需本品事实、行动承接 | 文案与画面逐段对应；源文、改写、主张和待补槽明确分开 |
| 拍摄 `cards.shooting` | 主体/动作/场景/景别/机位/光线/道具/声音、有效窗口、验收正反例、依赖素材 | 摄影可执行，剪辑知道要保留什么，未拍不称已完成 |
| 测试 `cards.test` | 假设、变更变量、尽量固定的条件、指标口径、观察窗口、样本不足及停止/复查条件 | 结果默认为未测试；有数据能追回准确版本，并保留混杂因素 |

按用户需要交相应内容；只要拍摄单不扩展任务范围。当前工具的完整工作台要求四卡齐全，每个变体都有脚本、拍摄及测试关联；局部内容可以单独交付，工作台则保留草稿/待补，不能为了 `--require-ready` 编造未授权或未知内容。已有拆解报告仍默认省略 `不可直接照搬`、`整片受众假设（非测量）`、`复刻素材清单`，目标创作卡不借此恢复被省略章节。

**探索 `exploration`**：本品尚无可复用实测基线，允许比较不同需求/框架/展示思路；明确一组变化及未知因素，不承诺能隔离单变量因果。先补关键证据，减少无依据脚本。**迭代 `iteration`**：有可追溯父版本，固定可复用部分并聚焦一个明确变量；记录 `parent_variant_id`、假设、`changed_variable` 和 `control_notes`。父版本未实测时仍可做编辑迭代，但必须写“未测试父版本”，不能称种子裂变。只有可比实测记录支持时，才在限定产品/日期/目标/样本下称“已测试可参考”。

创意内容改变时创建新的 `variant_id` 并关联父版本；不要在已经投放/关联报表的旧变体下覆盖脚本或拍法。`init --from-bundle` 只复制文件并递增 bundle 修订，保留原 ID，不会自动创建新创意；执行者须新增变体与对应卡。文件修订号不能替代平台创意到准确本地变体的映射。

镜像、抽帧、变速不是默认裂变策略；它们可能改变事实可读性且不能证明有效。优先有意义的解释变量：同一需求的切入方式、同一主张的展示机制、句子与动作的先后或承接。多因素一起变可以作为探索，但不能事后认定某一个因素导致差异。

## 6. 把报表接回下一轮内容决定

导入前明确创意 ID → 本地变体 ID → 产品 ID，记录平台、日期、目标、归因窗、曝光/点击/转化的定义和分母、价格/入口/定向等上下文。原始 CSV 与哈希保留；不能仅按相似标题匹配。不同目标、归因窗或条件分组比较，缺条件时写不可比。

反馈不是一套通用门槛。完整版 PDF 31 页明确提醒基线取决于自有产品与历史数据；短笔记 PDF 1 页的固定三秒率、业绩占比，以及其他预算、人数、产量不能变成工具默认值。用户未提供阈值时先报告观察与样本，不自造合格线。

用户明确指定“以 30% 三秒率筛选”时，保留为本项目拟定条件，写入测试卡 `success_criterion`；同时在 `metric_definition` 核对观看人数/次数、三秒口径与分母，并记录日期范围和最低样本要求。它不是通用品类门槛、统计显著性标准或成交种子证明。反馈 `sample_criteria` 只接收原始数量/金额下限，不能把 0.30 比率塞进去冒充样本要求；没有数据时只记录条件，不判达标。

每次复盘交三类结论：**观察**（按可比组发生了什么）→ **解释假设**（哪些内容机制可能有关，其他因素是什么）→ **下一行动**（保留/补证/再拍/再测什么）。例如“同一归因口径下版本 B 点击比例较高，转化量少且日期不同；优先核对入口与样本，再只替换演示方式复测”，不能写“B 镜头提高购买率”。

用反馈报告路径、版本 ID、口径与局限关联对应表达模块/测试方案，保留候选到已测试的升级依据和反例。当前 `cards.test.status` 固定保留 `untested`，表示原始测试计划；**实测结果独立保存在 feedback 状态与报告**，不能自创 `tested/winner` 状态绕过校验。测过不等于有效；有效过不等于跨产品有效。工具只做本地导入与报告，不建立广告计划、不提交预算。

手工回填格式示例（以下数值为合成）：`feedback/report-v1/report.json` 中 V01、V02 在同一比较组，各有 1000 次曝光，点击分别为 20/40、成交均为 2。保存到对应 `expression_modules[].conditions` 的复盘注记：**来源**为报告路径、`state_sha256`、两个 `result_id` 与变体 ID；**观察**为点击比例 2%/4%，成交数相同、样本有限；**解释假设**为 V02 可能更易被理解，但流量分配等仍可能有关；**下一行动**为新建 V03、父 V02，仅改演示顺序，补拍完整动作，保持商品/事实句/入口并记录差异。随后保存新 bundle 修订。原测试卡继续 `untested`，已发生观察由反馈报告承担；阶段提示不是这条内容决定的替代品。

## 可执行入口与自然语言路由

所有命令先用当前安装版本 `--help` 核实。以下均在 **Skill 根目录**运行；自动执行时解析成绝对脚本路径，用参数数组传路径。工作数据写独立项目目录。仓库用户也可用 `python scripts/project.py creative|feedback|batch ...` 转发；此根入口不随独立 Skill 安装。

```text
python scripts/creative_workflow.py --help
python scripts/creative_workflow.py init --help
python scripts/creative_workflow.py validate --help
python scripts/creative_workflow.py render --help
python scripts/creative_workflow.py search --help
python scripts/creative_workflow.py demo --help
python scripts/performance_feedback.py --help
python scripts/workflow_batch.py --help
```

当前版本可先运行合成示例熟悉格式，再建立自己的草稿；`init` 只建待填写模板，不会自动看视频或生成适合本品的内容。以下 `demo` 和 `init` 都用新目录：

```text
python scripts/creative_workflow.py demo --output <job>/creative-demo
python scripts/creative_workflow.py init --output <job>/creative-v1 --product-id <稳定产品ID> --product-name <产品名> --source-manifest <已复核脚本manifest.json>
python scripts/creative_workflow.py validate --bundle <job>/creative-v1/creative-workflow.json
python scripts/creative_workflow.py render --bundle <job>/creative-v1/creative-workflow.json --output <job>/creative-v1/report
python scripts/creative_workflow.py search --root <job> --query <需求或动作关键词>
python scripts/performance_feedback.py init --output <job>/feedback
python scripts/performance_feedback.py import --state <job>/feedback/feedback_state.json --csv <后台导出.csv> --mapping <已填写映射.json> --registry <job>/creative-v1/creative-workflow.json
python scripts/performance_feedback.py report --state <job>/feedback/feedback_state.json --output <job>/feedback/report-v1
```

没有参考视频时省略 `--source-manifest`。先由执行者把本品事实、分析及四卡写入草稿，再校验和渲染；`READY_FOR_HUMAN_REVIEW` 表示可交内容审阅，仍不证明事实/语义/听校完成。检索是关键词全部匹配，不是语义推荐。反馈映射须先填写真实列名、口径和创意映射，不直接导入模板中的示例值；更正已导入数据用当前 `import --help` 中的 `--operation upsert --reason` 并保留历史。

| 用户可直接说 | Agent 应采取的路径 |
| --- | --- |
| “按课程方法拆这个视频，原文和画面分别解释” | 原流程转写/来源/语义段/逐画面，应用本参考第 1 节；不建生产卡 |
| “给这个产品出选题、脚本、拍摄单和测试卡，事实不足保留待补” | 先核本品资料和参考身份，`creative init` 后补 bundle、校验、渲染；用 `search` 找已存模块/选题 |
| “这个卖点再给几种真实可拍的表现方式” | 查事实支持范围，比较不同机制，交选中/淘汰理由与拍摄卡；不凑数量 |
| “继续拆这个文件夹，已完成的别重做” | `batch add/run/status`，查看逐阶段状态；人工复核后 `attach` 当前 manifest/receipt，再运行导出 |
| “把这个 CSV 接回之前几个创意，告诉我下一轮改什么” | `feedback init/import/report`，先补映射、口径与变体注册表；不把未知创意强配旧版本 |

一条完整的原创应用：用户只核实了收纳盒外形尺寸和可拆隔板，想服务“早上找小配件”的情境。先记此需求为假设，检索真实尺寸疑问；选“购买前怎样核对尺寸与分区”为题。外形尺寸不等于内腔/可用尺寸，柜体适配还需净空、铰链占位与开合余量。参考片扣卡扣不能证明本品也有卡扣；未核实前不安排该动作。脚本先说已知尺寸与结构，画面用量尺→拆装隔板；装入物件与推合等样品、物件及柜体实测后再补，不写节时或承重结论。拍摄卡规定刻度可读、连接处不遮挡、过程连续。可先交结构展示，布局演示作为有依赖的备选；证据不足不造第三个。测试卡标探索、未测试，比较信息顺序，保留价格/入口与实际曝光条件，收到报表后再决定是否成为可复用模块。

## 交付前内容复核

先挑一个普通段和一个否定/引用/声画冲突段独立复核，再批量展开。复核者要能从卡或段落回到原句、时间与镜头；区分观察、主张、目标产品事实、推断和建议；确认缺口仍可见；看拍摄要求是否真的可操作。来源/字段/哈希校验 PASS 只证明结构相容，不能声明听校、语义、功效、市场人群或投放结果通过。

常见退回：只有销售标签没有动作；把画面观察写成“强信任”；把三个景别叫三个卖点机制；复制源片经历给本品；买评当需求研究；对不同比较组统一排名；把课程比例当默认阈值；只写“多测多拍”没有变量/材料/下一步。
