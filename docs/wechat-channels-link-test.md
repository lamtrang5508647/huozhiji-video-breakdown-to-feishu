# 视频号分享链接真实测试

日期：2026-10-08；Windows、已安装 Chrome、独立临时浏览器会话。
测试输入为用户提供的一条 `weixin.qq.com/sph/` 分享短链。
真实链接、平台文案、作者、页面截图和跳转参数只留在本机忽略目录。

## 已观察到的结果

统一 `project.py acquire --download` 入口正确识别为 `wechat_channels`，
但当前没有显式配置 Provider，返回 `blocked / provider_not_configured`。
该入口未调用后端或下载媒体。

另外直接通过浏览器只读访问腾讯分享页：原短链以 HTTP 301 跳到
`channels.weixin.qq.com/finder-preview/pages/sph`，返回 HTTP 200。
预览中可见目标文案、作者、日期、封面和“可扫码前往微信观看此内容”的二维码。
DOM 中没有 `video` 或 `source` 元素，本次网络响应没有视频流；取得的 HTML
也没有 `videoUrl`、`objectDesc`、`feedInfo`、`.mp4` 或可比对的原生视频对象字段。

页面中的观看二维码用于在微信打开内容，不是给提取程序建立登录会话的授权入口。
预览的 `id` 查询字段不能仅凭字段名当作原生视频 ID。分享 token、封面和 HTTP 200
同样不能证明已取得原片。

## 验证边界

本次验证了链接的腾讯预览页面可访问，以及未配置后端时的真实阻塞行为。
目标原生 ID、Provider 的来源绑定、媒体下载、完整解码及源哈希仍为**未验证**。
未生成 `source.json`，没有飞书写入、语音转写或脚本分析。

当前项目实现的是视频号 Provider 适配器，尚未配置可用于真实提取的后端。
即使随后接入后端，也必须先验证原分享链接与实际视频对象的绑定，再验证媒体。
本次没有启用第三方解析器、读取 Cookie、安装代理或证书、启动抓取服务或解密媒体。
