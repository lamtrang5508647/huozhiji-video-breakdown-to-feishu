# 飞书初始化与字段映射

源码与实际项目分离。先使用 `scripts/project.py init` 建本地目录，再绑定用户本次选择的
Base 与身份。配置不保存 app secret、访问令牌、Cookie 或密码，认证由 lark-cli 管理。

## 五张逻辑表

| 配置键 | 职责 | 主要关联 |
| --- | --- | --- |
| `videos` | 原标题、来源、原片、转写、进度、整片框架 | 产品、脚本段、画面素材、分析章节 |
| `segments` | 完整语义段、时间、功能、公式、情绪与段落视频 | 源视频、产品、素材片段、文档 H2 |
| `materials` | 逐画面切片、标签、字幕摘录、复用判断 | 源视频、所属脚本段、产品平台 |
| `products` | 稳定产品编码、业务名、素材入口 | 平台目录 |
| `platforms` | 产品 × 平台的导航 | 原片、脚本段和画面素材画廊 |

同名表不等于同一对象，以明确的表 ID 为准。新目标不需要使用旧项目的中文显示名，
但必须保留程序所需的字段含义与类型。`skill/analyze-folder-videos-to-feishu/assets/project_profile.example.json` 展示
完整字段映射形状；选项值和资源 ID 必须来自新目标的实时结构，不能沿用示例。
素材复用、场景细分等字段属于扩展，配置中声明的每个字段都必须与实际表一致。

## 实际接入步骤

1. 确认目标 Base URL、可用的 `bot` 或 `user` 身份、应用公开 ID，以及预期的人类编辑者。
2. 读取已存在的表、字段、选项、关联方向、视图和文档。需要新建时先复用已有对象，
   在本次任务授权范围内创建缺失对象；不能仅按同名猜对象。
3. 填写五张表的 ID 和字段映射，将实时字段响应保存到配置指定的 `fields_snapshot`。
   快照是 `{"ok": true, "data": {"fields": [...]}}` 结构，字段含真实 `id/name/type`，
   选择字段还要保留 `options` 与 `multiple`；关联字段保留目标表元数据。
4. 在新目录初始化 profile，或编辑当前明确选中的本地配置。用 `check_project.py --live`
   检查身份、Base、表及已经登记的文档；该检查不代替写入前的实时字段比对。
5. 建立产品与平台记录、三个对应画廊；素材画廊封面使用视频附件字段。
6. 首条视频分析、素材导出和复核完成后，创建产品 × 平台汇总文档，核对编辑权限，
   将实际 doc token、组键与元数据登记到 `state/platform-document-registry.json`。
   文档标题可用 `<产品>竞品｜<平台>拆解`；组键依赖稳定 ID，不依赖这个标题。
7. 构建可审阅的上传计划，再用同步器的显式执行参数写入。回读源视频、段落、
   素材及实际画廊，再更新文档章节和状态；超时先检查远端，不能盲目重传。

初次创建表和文档由执行者使用当前可用的飞书工具完成；本仓库未封装一键建完整 Base。
直接运行 `publish_platform_chapter.py` 不会创建新的组文档。
注册表结构和章节更新规则见 Skill 的 `platform-docx-aggregation.md` 与
`golden-layout-and-delivery.md`。所有权与编辑权限见 `document-access.md`。

## 显示名可以更换

```json
{
  "来源链接": {"id": "fld_REPLACE_SOURCE", "name": "Source URL", "type": "text"},
  "来源平台": {"id": "fld_REPLACE_PLATFORM", "name": "Platform", "type": "select"}
}
```

映射的键是程序的标准字段名，`name` 是该目标表实际显示名，`id/type` 必须与实时字段
一致。省略 `name` 时表示实际列名与标准名相同。不能把两个标准字段映射到同一个字段。

## 来源身份与平台

```json
{
  "video_id": "123456789",
  "source": {
    "platform": "抖音",
    "url": "https://www.douyin.com/video/123456789",
    "sha256": "由实际原片计算的64位SHA256"
  }
}
```

这是结构示例，不是真实视频。计划中的来源、表中已有源视频记录和本地文件哈希必须
相互匹配。来源 URL 不包含明确视频 ID 时，配置
`"source_identity": {"id_field": "来源视频ID"}`，并在源视频表映射且预先填写该字段。
短链接重定向本身不会由同步器当作已核验的原视频身份。

对其他平台使用明确 URL 匹配；不以标题或 URL 子串碰巧相同代替身份核验。
下载原片是独立步骤，支持本地文件并不等于支持平台抓取。

## 权限、归档和验收

- `expected_base_owner_id` 与 `document_owners` 填已核验的账号 ID。
  未配置所有者时，回执必须说明未核验；不能把缺省配置当作已确认权限。
- 原片附件、完整转写和用户参考文件保留，不被标色分析或生成建议覆盖。
- 视频章节更新按实际锚点进行，不重写整个汇总文档；发现人工改动先对比。
- 剪辑复用、AI 重制、选材优先级和归档是不同字段含义。归档通过标签与视图隐藏，
  不删除可追溯的原记录与片段。
- `verify_material_gallery.py` 检查真实附件、归属、关联、筛选结果与封面。
  API 成功不代表用户界面已实际播放，需分开报告。

## 通用版的计划格式收紧

`build_video_base_plan.py` 必须显式提供 `--review-receipt`，它指向连续段导出时
使用的原审核回执。计划会绑定该回执、manifest、原时间线、导出报告、CSV、
片段和缩略图的哈希；同步前再次回读这些文件。保留整个任务目录，不能只搬一个 plan JSON。
从另一台机器迁移时先按原片哈希恢复任务文件，再重新构建计划。

本版本旧计划需用新 builder 重建，不能手工补一个“已审核”状态绕过校验。
业务键包含视频身份与版本；源段 ID 仍用于媒体索引和文档链接。
没有远端读回或实际播放验证时，分别标为未验证，不能合并进“全部完成”。
