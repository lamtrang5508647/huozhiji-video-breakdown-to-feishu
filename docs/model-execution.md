# 跨模型执行与复核

统一输入、渲染和验收可减少模型之间的输出差异，但不能保证不同模型具有相同的
视觉理解、转写或语义判断能力。模型名称来自实际运行环境，不能把期望型号或代理名
写成已经执行的型号。

## 分工

1. 规划者绑定原片、产品、平台与目标；划分完整脚本段，确定疑难词和需复核镜头。
2. 执行者逐段读取原片证据，填写结构化分析；不能只看上一条样板替换词语。
3. 确定性程序检查来源、字符、时间、镜头归属、重复与排版。
4. 独立复核者检查原文、短语功能、公式、品牌、情绪依据与素材适用条件。
5. 单一发布者将通过复核的版本串行同步，并核对保存结果。

先验收一条有难例的小样，再扩大批次；争议项留待判断，不用统一颜色或“已审核”字样
填平差异。原片、标注或上下文发生变化后，旧的审核哈希不能用于新版本。

## 必须稳定的输出

- 视频原标题使用 H1；原片结构公式、可复用变量公式、图例、每个脚本段使用 H2。
- 标色作用于原文中的短语区间，同一句可以多种颜色。不能按段落位置或关键词批量染色。
- “来源陈述”“结果主张”“个人体验”“未来计划”“行动请求”分别依据上下文判断。
- 原文、观察、推断、复刻建议分开；情绪与受众反应不能伪装成后台测量数据。
- 默认简化展示不加 `不可直接照搬`、`整片受众假设（非测量）`、`复刻素材清单`。
- 关键帧用于证据与预览，素材库的交付物包含实际视频片段。
- 剪辑复用和 AI 重制分别判断；没有调用和检查生成服务就不能标“生成已验证”。
